ScoreFlow - Documento de Contexto V1.0

1. Visão Geral e Stack Tecnológica

Produto: SaaS de gestão completa de campeonatos de ginástica (iniciando pela modalidade Rítmica). Substitui planilhas/WhatsApp por plataforma unificada.

Modelo Multi-tenant: Um único código atende N federações. Dados isolados por federation_id usando Row Level Security (RLS) do banco.

Stack Definida:

  • Front-end: React + Vite + TypeScript.
  • Estilo/UI: TailwindCSS + shadcn/ui (Temas: Zinc, Estilo New York).
  • Estado/Business: TanStack React Query (servidor), Zustand (global/interface), React Hook Form + Zod (formulários/validação).
  • Back-end/Banco: Supabase (PostgreSQL, Auth, Storage, Realtime/WebSockets). NÃO usar Firebase por causa da complexidade de relações e cálculos.

Portais:

  • scoreflow.app: Sistema operacional (Federação, Clubes, Árbitros). Requer login.
  • fmg.com.br (ex): Portal público da federação (Painel de notas, resultados). Sem login.
  • scoreflow.com.br: Portal global agregador (V2).

2. Arquitetura de Dados e Segurança

Separação de Usuários (3 Camadas):

  • auth.users: Tabela interna do Supabase (senha, email, tokens).
  • profiles: Linka com auth.users. Contém role (FEDERATION_ADMIN, CLUB_ADMIN, JUDGE, SYSADMIN) e federation_id.
  • federations: Tabela de inquilinos (Nome, Sigla, Logo, etc).

Dados Mestres (Master Data) vs Dados de Tenant:

  • Master Data (Admin): Tabelas como apparatus (Aparelhos) e base_categories (Categorias base). Não têm federation_id. Gerenciados apenas pelo SYSADMIN. As federações apenas "selecionam" esses dados ao criar campeonatos.
  • Tenant Data: Tabelas como clubs, athletes, championships. Têm federation_id. Protegidas por RLS.

Segurança (RLS): Todas as queries do front usam o perfil logado. O Supabase bloqueia no banco qualquer tentativa de leitura/escrita de dados de outra federação. Nunca confiar apenas no front-end para isolar dados.

3. Atores e Permissões

  • SYSADMIN (Eu): Acesso ao Painel Admin para cadastrar Aparelhos, Categorias Base, gerenciar federações clientes.
  • FEDERATION_ADMIN: Gerencia campeonatos, vincula aparelhos/categorias, convida clubes/árbitros, aprova transferências (V2), visualiza tudo de seu tenant.
  • CLUB_ADMIN: Cadastro via link de convite. Gerencia atletas, comissão técnica, documentos. Faz inscrições em campeonatos.
  • JUDGE: Papel estrutural. Recebe convites para campeonatos. No dia, pode assumir o papel de Avaliador (D, E) ou Coordenador de Arbitragem (papel de contexto definido na tabela do campeonato).

4. Requisitos Funcionais Completos (V1.0)

Épico 1: Gestão da Federação

  • Tela de Perfil (Editar dados, endereço, redes sociais, logo).
  • CRUD de Árbitros (com envio de e-mail de convite via Supabase Auth).
  • Visualização de Clubes filiados (ver atletas e comissão técnica).
  • Geração de Link de Convite para Clubes.
  • Controle de Status de Campeonatos (Iniciar, Finalizar).

Épico 2: Campeonatos

  • CRUD (Nome, local, datas, upload regulamento PDF).
  • Configuração de Documentação Obrigatória (regras dinâmicas do que atletas/treinadores precisam anexar).
  • Vinculação de Aparelhos e Categorias (puxando do Master Data do Admin).
  • Cálculo de Inscrição (apenas exibição baseada em nº de atletas, sem gateway de pagamento na V1).
  • Geração de Link de Inscrição na tela do campeonato.
  • Ordem de Apresentação: Drag-and-drop (@dnd-kit). A mesma ordem de ginastas se repete para aparelhos da mesma categoria. Botão de aleatorização.
  • Gestão de Arbitragem: Vínculo de juízes ao camp (função D, E, DB, DA, Coord). Opção de criar juiz "temp" ou de outra federação. Disparo e-mail de convocação.

Épico 3: Fluxo de Clubes

  • Cadastro via Link (escolhe modalidade).
  • Perfil do Clube.
  • CRUD Atletas (por modalidade, upload de fotos/docs gerais).
  • CRUD Comissão Técnica.
  • Tela de Inscrição: Acessar link do camp -> ver categorias -> adicionar atletas -> anexar docs obrigatórios -> alerta de pendências.

Épico 4: Apuração em Tempo Real (O Coração)

  • Tela Árbitro (Avaliador): Fica em "Aguardando". Via WebSocket, muda para tela de avaliação (nome, equipe, aparelho). Caixa de texto para nota. Envia.
  • Tela Diretor Arbitragem: Seleciona dia. Vê categorias. Corta ginasta (lesionada/faltou). Clica "Ativar Avaliação" (dispara WebSocket para os árbitros).
  • Painel de Notas do Diretor: Recebe notas do WebSocket. Mostra caixas por árbitro. Pode alterar nota (salva em campo notaAlteradaPeloDiretor e novo valor). Botão "Validar/Publicar".
  • Cálculo FIG: 2 juízes = média simples; 3 juízes = média simples; 4 juízes = média interna (descarta maior e menor, tira média das duas do meio).
  • Cálculo Individual Geral (soma aparelhos).

Épico 5: Portal Público e Relatórios

  • Listagem camp ativos (público).
  • Painel de Divulgação (última nota validada via WebSocket).
  • Tabelas de Classificação (atualizadas em tempo real).
  • Exportação Word (ao finalizar camp, gerar doc formatado com tabelas de resultado por categoria e geral usando lib docx).

5. Plano de Sprints (Ciclos de 2 Semanas)

SPRINT 1 & 2 Fundação & Catálogos (Admin)
Criar role SYSADMIN. Tabelas globais (Aparelhos, Categorias Base). CRUD no Painel Admin (com upload imagens). Tela Perfil Federação. Gestão de Árbitros (CRUD + convite email).

SPRINT 3 & 4 O Mundo dos Clubes
Sistema convite clubes (Token URL). Cadastro clube (modalidade). CRUD Atletas e Comissão (Upload docs Storage). Perfil Clube. Ajustes RLS.

SPRINT 5 & 6 Campeonato Estático
CRUD Campeonato. Vincular aparelhos/categorias (Select do Admin). Upload regulamento. Config docs. Link inscrição. Tela inscrição Clube (add atletas, upload docs, cálculo taxa).

SPRINT 7 & 8 Ordens e Arbitragem
Módulo Ordenação Apresentação (dnd-kit, lógica mesmos aparelhos, botão aleatório). Gestão Arbitragem no camp (vínculo, funções, temp, email convite). Tela inicial Árbitro (convocações).

SPRINT 9, 10 & 11 O Coração ao Vivo (Crítico)
Tela Diretor (dias, cortar atleta, ativar avaliação). Supabase Realtime (WebSockets). Tela Árbitro (aguardar -> receber -> digitar -> enviar). Painel Notas Diretor (receber, alterar, auditoria, validar). Cálculo FIG (Médias).

SPRINT 12 & 13 Divulgação e Fechamento
Portal Público (Listagem, Painel divulgação WS, Tabelas classificação). Relatório Word (lib docx). Polimento geral e testes.

6. Contexto de Negócios (Restrições)

  • Equipe: Apenas o desenvolvedor (estudante de Eng. Computação) + Arquiteto (IA).
  • Cliente Piloto: Federação Mineira de Ginástica (FMG). Relação pessoal (mãe do dev). Foco em entregar valor rápido, não em cobrar caro agora.
  • Modelo Cobrança: Isenção de mensalidade para FMG. Eles pagam apenas Taxa de Implantação simbólica e Custos Operacionais (Supabase Pro ~R$ 130/mês). O dev retém os direitos do SaaS para vender para outras federações futuramente.
  • Tempo Real: Obrigatório no MVP. Usar Supabase Realtime (WebSocket). Sem off-line no momento.
